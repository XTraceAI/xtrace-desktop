# Fixture harness acceptance

This contract covers `xt-fixtures`, the synthetic catalog and fixture commands in
`xtask`. It does not establish ingestion, product metrics or desktop integration.
Every PR changing this boundary records its tested source/base, commands, actual
results and remaining checks.

| Case                               | Setup and action                                                                                                                                 | Expected result                                                                                                                                                                                                   |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Catalog and coverage               | Load all entries and run `cargo xtask fixture-validate`.                                                                                         | Exactly 21 entries load in numeric order: F1 is populated and reference-asserted; F2–F21 report skeleton/unimplemented. Missing, zero-padded or mismatched IDs fail.                                              |
| Deterministic baseline             | Build F1 twice in separately owned temporary directories; compare sessions, records and child data.                                              | Logical rows match: 25 records, 15 usage observations and five tool calls. Paths and database bytes are not the determinism contract.                                                                             |
| Independent expectations           | Evaluate the stored F1 rows; separately mutate an input counter and the token golden.                                                            | Baseline has five human messages, five assistant turns, ten selected responses totaling 1,100 tokens, 23 active minutes and one model. Both mutations fail; summing all usage rows to 1,775 tokens does not pass. |
| Database ownership and WAL         | Hold a reader snapshot while the owner commits another record; end the snapshot, close readers and drop the owner.                               | The held snapshot sees 25 rows, the next read sees 26, and the temporary database remains until its owner is dropped.                                                                                             |
| Database export                    | Export F1, reopen the closed SQLite file, then repeat the export or supply an existing SQLite sidecar.                                           | The standalone file contains all 25 records and 15 usage rows. Existing files and sidecars are never overwritten; rejected output leaves existing bytes intact.                                                   |
| Canonical export and identity      | Export loaded records and auxiliary stubs; vary declared hosts and present/absent raw platforms.                                                 | Library and CLI use the same data. Null remains distinct from zero, absent raw platforms remain unknown, explicit raw platforms retain mapping validation and skeleton exports retain their status.               |
| Manifest paths and malformed input | Use a custom declared input path; try missing files, traversal, escaping symlinks, invalid UUIDs/times, unknown rules and duplicate golden keys. | Custom paths load. Invalid cases fail with source locations; literal, conflicting and escaped-equivalent duplicate keys fail at every object depth, including inside arrays, before a map can discard them.       |
| Skeleton boundaries                | Put canonical records in the first session, second session or both; try nonempty/null expectations and evaluation/database creation.             | Nonempty canonical input or expectations fail. Empty/whitespace-only inputs load; evaluation and database creation return unimplemented instead of success.                                                       |
| Content retention                  | Build F1 with content retention enabled and disabled, inspecting records and tool projections.                                                   | Structural counts and identities match; disabled retention stores no message content or tool input. This operation does not purge previously saved content.                                                       |
| CLI failures                       | Run invalid commands/options, missing catalogs, exports to existing paths and skeleton database requests.                                        | Commands exit nonzero with useful diagnostics; failed requests do not report successful output.                                                                                                                   |
| Combined integration               | Run full workspace, UI/browser, local native, notice/SBOM and source checks on the current source/base.                                          | Existing shell behavior passes, lockfiles remain frozen, dependency notices reproduce and the synthetic development library is not connected to product capture or metrics.                                       |

Run `cargo test -p xt-store -p xt-fixtures -p xtask --locked` and
`cargo xtask fixture-validate` for focused verification. Follow [CI.md](../CI.md)
for full validation, including local native checks and hosted Linux CI. Tests use
synthetic inputs and disposable databases; only executed populated assertions
count toward fixture acceptance.
