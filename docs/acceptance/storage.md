# Canonical SQLite storage acceptance

This contract covers the `xt-store` library. The desktop app opens the store on startup;
automatic capture ingestion remains separate. Every PR changing this boundary records the tested
source/base, commands, actual test counts and remaining checks.

The database records fingerprints for newly applied migrations. Older databases
without fingerprints must have compatible table, column, index and trigger
definitions before fingerprints are initialized. SQL formatting and comments
are ignored; quoted values and identifiers remain exact. This checks the current
schema's compatibility, and cannot recover an older build's historical SQL.
Synthetic upgrade tests cover every schema version through 23 and a healthy
public 0.1.2 database built from its exact 22 migration files. Refused synthetic
files with changed constraints, indexes or triggers remain byte-identical.

| Case                         | Setup and action                                                                                                                                               | Expected result                                                                                                                                                                                                                       |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Connection settings          | Open a temporary file database and an isolated in-memory database; inspect connection pragmas, then reopen a second connection to the same file.               | Every file connection uses WAL, FULL synchronous mode, foreign keys and a five-second busy timeout; macOS also enables fullfsync. Memory mode retains MEMORY journal and NORMAL synchronous mode.                                     |
| Migration and reopen         | Open/migrate a fresh file twice, persist rows and reopen it; force a migration failure and add an unknown version to the history.                              | Version 1 applies once. Reopening preserves rows. A failed migration rolls back, and incompatible history is rejected. Migration source filenames do not change stored numeric versions.                                              |
| Readers and writers          | Use independent file connections; hold a read snapshot while another writer commits; run concurrent writes.                                                    | Readers see a consistent committed snapshot, writers serialize and committed rows persist. Assertions use file-backed WAL rather than in-memory substitutes.                                                                          |
| Replay and enrichment        | Import a batch twice in both source arrival orders, then fill missing fields and replay poorer/conflicting input.                                              | Each UUID inserts once. Null values remain unknown until measured; known values do not disappear. Conflicts keep the first known value and set a structural flag.                                                                     |
| Identity and atomicity       | Supply missing UUIDs, same-batch duplicates, UUIDs already owned by another session, different record types and an invalid record after valid input.           | Missing UUIDs are counted and omitted; duplicates observe earlier updates in the same batch. Existing ownership/type cannot change. Invalid input rolls back the whole batch.                                                         |
| Retention                    | Insert and enrich with content retention disabled, alongside previously retained content; inspect every content-bearing column and tool projection.            | No new titles, message content or tool input are retained. Structural lengths/counts, identities and usage survive. Existing saved content remains; no purge is implied. Conflicting arrays cannot provide newly retained tool input. |
| Wire and structural evidence | Round-trip supported aliases, unknown platform/surface values and native IDs; try invalid counters or extra/path/content fields in structural evidence.        | Unknown values stay distinct from zero; valid raw identities survive. Negative counters and invalid structural evidence fail.                                                                                                         |
| Timestamp precision          | Use reverse-UUID sub-millisecond records, fractional digits beyond nanoseconds, equivalent offsets, pre-epoch times, missing times and leap-second boundaries. | Ordering and session bounds follow precise instants. UUID breaks equal-instant ties only; missing times are last. Equivalent instants do not create conflicts.                                                                        |
| Bounded session reads        | Instrument a 1,000-record session with usage/tools plus another session; read all records.                                                                     | At most three SELECTs read records and children from one snapshot, preserving ordering, attachment and session isolation.                                                                                                             |
| Bounded replay reads         | Replay/enrich 10,000 records with SQLite limited to 999 bind parameters; instrument SELECTs and include unrelated rows.                                        | At most 63 SELECTs include one retention-policy read and prefetch only incoming UUIDs and children. Sequential enrichment, sticky conflicts and ownership remain correct.                                                             |
| Integration                  | Run full workspace checks, UI/browser checks, native debug build/launch and updated dependency-artifact checks on the combined source/base.                    | Existing shell behavior passes; lockfiles stay frozen; notices reproduce and the validated SBOM includes the SQLite dependency chain. Library tests do not imply that ingestion or UI integration is delivered.                       |

## Pull-request evidence

These cases run under `cargo test -p xt-store --test pr_link`. They use synthetic
GitHub identities and disposable file databases; no network, Git, scanner or UI
path is exercised.

| Case                                                                     | Setup and action                                                                                                                                              | Expected result                                                                                                                                                                 |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `canonical_urls_normalize_case_and_round_trip`                           | Parse case variants of scheme, host, owner and repository, plus the largest number and longest owner/repository.                                              | All variants yield one lowercase `owner/repo`, number and canonical URL; distinct repositories and numbers stay distinct.                                                       |
| `unsupported_or_malformed_urls_are_rejected`                             | Supply userinfo, ports, other hosts/schemes, queries, fragments, extra/missing segments, dot traversal, escapes, `.git`, invalid numbers and oversized input. | Every input fails as invalid input; controls, whitespace and non-ASCII identity components never pass.                                                                          |
| `supplied_url_repository_and_number_must_reconcile`                      | Combine URL, repository and number observations, including case-only differences and conflicting or incomplete parts.                                         | Case-only differences reconcile to one identity; any other disagreement, or neither a URL nor repository plus number, fails.                                                    |
| `one_stub_and_one_link_per_canonical_identity`                           | Link one pull request twice through different spellings and once from a second session.                                                                       | One `pull_requests` row with the canonical URL and one `pr_links` row per session; the replay reports no change.                                                                |
| `duplicate_and_reversed_arrivals_converge_on_the_widest_interval`        | Apply overlapping and duplicate observation intervals in three orders.                                                                                        | Every order stores the earliest first-seen and latest last-seen time; an identical replay changes nothing.                                                                      |
| `confidence_upgrades_but_never_downgrades`                               | Apply confidence sequences in increasing, decreasing and mixed order.                                                                                         | Confidence moves only toward `exact > sha > inferred`; weaker evidence never downgrades a link.                                                                                 |
| `invalid_observations_and_missing_sessions_write_nothing`                | Link an unknown or blank session and an inverted interval.                                                                                                    | Each attempt fails and both tables are unchanged.                                                                                                                               |
| `late_failures_and_conflicting_rows_roll_back_stub_and_link_together`    | Inject a link-insert failure after a new stub, then add existing rows whose URL, repository or number disagree with canonical identities.                     | The injected failure leaves no stub; each conflict fails for either session without changing any row; readers reject a non-canonical stored identity instead of re-spelling it. |
| `links_persist_across_reopen_and_read_in_deterministic_order`            | Link several pull requests from two sessions, close and reopen the file.                                                                                      | The schema version is unchanged and readers return repository/number/session order after reopen.                                                                                |
| `exact_links_leave_merge_and_refresh_state_unknown_and_store_no_content` | Record an exact link, then inspect every pull-request column, the link row and other tables.                                                                  | State, merge time, sizes, title, branch and refresh time remain NULL; the link holds only identity, confidence and times; no other table changes.                               |
| `identity_readers_report_legacy_conflicts_instead_of_absence`            | Add legacy case-variant, URL-alias, split and duplicate-candidate rows with links, then read each identity through `pull_request` and `pull_request_links`.   | Both readers and the writer return the same conflict error; a unique canonical row still reads, an unknown identity is absent, and no row is rewritten.                         |

These cases establish identity and persistence only. Native `pr-link` scanning
and ownership of copied or rejected evidence are covered by
[native PR witnesses](native-pr-witnesses.md); refresh persistence is covered
below. Fetching from Git/GitHub and PR metrics are later work and are not claimed
complete here.

## Pull-request refresh status

These cases run under `cargo test -p xt-store --test pr_refresh`. They persist
typed synthetic results for rows created by exact links; no GitHub client,
subprocess, network, scheduler, app command or UI is exercised.

| Case                                                                      | Setup and action                                                                                                                                                                      | Expected result                                                                                                                                                                                                                                               |
| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `migration_8_adds_nullable_status_columns_and_preserves_rows`             | Rewind a store to schema 7 with a link stub and a legacy refreshed row, reopen twice, then try invalid raw status writes and refresh the legacy row.                                  | Version 8 applies once; every prior value survives and the two new columns are NULL. The schema rejects untyped codes, a code without an attempt, a text or negative attempt and an attempt before `refreshed_at`. The legacy `refreshed_at` orders attempts. |
| `successes_store_open_closed_and_merged_metadata_without_touching_links`  | Record one success for each state.                                                                                                                                                    | Every refresh-owned field, `refreshed_at` and `last_attempted_at` equal the attempt, no error, status `Refreshed`; links and row count are unchanged.                                                                                                         |
| `a_newer_success_replaces_every_refresh_owned_field_and_clears_the_error` | Record a merged success, a newer failure, then a newer closed success with different values.                                                                                          | All refresh-owned fields are replaced (merged time becomes NULL) and the error clears.                                                                                                                                                                        |
| `every_failure_code_preserves_the_last_successful_metadata`               | After a success, record each of the nine failure codes in turn; fail a never-refreshed row.                                                                                           | Only the attempt time and code change; status is `FailedAfterRefresh`, or `FailedNeverRefreshed` with all metadata unknown.                                                                                                                                   |
| `malformed_results_unknown_identities_and_conflicts_write_nothing`        | Submit blank, control-bearing or oversized title/branch, negative sizes, missing/invalid/forbidden merge time, out-of-range attempts, unknown identities and legacy conflicting rows. | Each fails as invalid input, even when older than the stored attempt, and no row changes; no stub is created.                                                                                                                                                 |
| `an_injected_write_failure_rolls_back`                                    | Make the update fail with a trigger for a success and a failure.                                                                                                                      | The call fails and nothing is committed; the same attempt applies after the trigger is removed.                                                                                                                                                               |
| `older_attempts_are_stale_and_write_nothing`                              | Submit successes and failures older than the stored attempt.                                                                                                                          | Each returns `Stale` with no mutation; a newer failure is the watermark for later successes.                                                                                                                                                                  |
| `equal_attempts_replay_identically_or_conflict`                           | Replay an identical success and failure at the stored time, then submit differing successes or failures at the same time.                                                             | Identical replays are `Unchanged`; every difference, including another spelling of the same merge instant, is a conflict and writes nothing.                                                                                                                  |
| `status_persists_across_reopen_and_reads_in_deterministic_order`          | Leave four rows in different statuses, close and reopen.                                                                                                                              | `all_pull_requests` returns identical rows by repository then number and matches `pull_request` for each.                                                                                                                                                     |
| `only_typed_codes_are_stored_and_no_other_table_changes`                  | Record every code and a success, then inspect the column list and other tables.                                                                                                       | `pull_requests` gains only `last_attempted_at`, `refresh_error` and (migration 23) `manual_failed_at`; only the typed code is stored; no other table changes.                                                                                                 |

Run `cargo test -p xt-store --locked` for focused cases and follow
[CI.md](../CI.md) for full workspace, browser, native and supply-chain validation.
Tests use synthetic records and disposable databases.

Connection tests verify SQLite configuration, and existing file/reopen tests verify
committed rows remain readable. They do not simulate hardware power loss.
