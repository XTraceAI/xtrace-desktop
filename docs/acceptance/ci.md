# CI acceptance

Each PR records its tested source head, base, run URLs and actual results. This
contract defines the cases to verify; it does not claim every case has been run
against a particular revision. Disclosure review remains manual.

| Case                      | Setup and action                                                                                                                                                              | Expected result                                                                                                                                                                                                                                                      |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Source validation         | Frozen install; run UI types, lint, formatting and unit tests; workspace Rust fmt, strict all-target/all-feature Clippy and all-feature tests.                                | All commands succeed without lockfile changes. Report actual test counts; empty Rust scaffolds claim compilation only.                                                                                                                                               |
| Runner cost boundary      | Inspect the hosted job platforms and browser install step on the exact candidate.                                                                                             | Policy, UI, security, aggregation and text-edit policy use Ubuntu 24.04. Routine CI has no native jobs. Explicit release validation uses macOS 14 arm64; local validation records its actual OS. Both browsers pass with Linux system dependencies installed.        |
| Browser boot              | Start a fresh server through `pnpm e2e`; run WebKit and Chromium.                                                                                                             | Visible shell, bundled brand/font assets, honest browser-only status, no page/console errors or external boot requests.                                                                                                                                              |
| Credential isolation      | Test the actual workflows' checkout, permissions and token assignments.                                                                                                       | Candidate code receives no metadata token. Contribution validation executes only reviewed default-branch or explicitly pinned bootstrap code. Missing policy fails.                                                                                                  |
| Contribution descriptions | Submit substantive Change/Verification sections on ordinary contributor branches; separately try missing sections and untouched placeholders.                                 | Useful descriptions pass on ordinary contributor branches. Missing or placeholder-only sections fail.                                                                                                                                                                |
| DCO and source selection  | Use disposable Git histories and PR/merge-group API fixtures with signed/unsigned commits, incomplete pagination and changing metadata.                                       | Every actual source commit needs its author's final sign-off. Bootstrap or synthetic commits cannot substitute; incomplete or changed inputs fail.                                                                                                                   |
| Squash merges             | Validate an author/trailer mismatch as a source PR and separately as the resulting default-branch push; test invalid push identities.                                         | The source PR fails DCO. Post-merge validation does not re-certify a provider-created squash commit, and rejects wrong repository/branch or malformed identities.                                                                                                    |
| Aggregation               | Exercise each of the three declared jobs as missing, skipped, cancelled or failed.                                                                                            | Every negative case fails `ci-ok`; all three successful jobs pass.                                                                                                                                                                                                   |
| Metadata routing          | Edit PR text; separately test target-branch edits and overlapping target/text events.                                                                                         | Text-only edits run reviewed policy without a new app build or replacement source result. Target changes run full CI and survive subsequent text edits. Record live text-edit evidence and distinguish synthetic target-routing coverage.                            |
| Manual publication        | Exercise manual default/non-default dispatch and reject all former automatic events before API access.                                                                        | Only explicit default-branch audits can run. No schedules, review relay or event-driven scans remain. The comprehensive local review is required before public visibility and the first downloadable release; routine solo-maintainer PRs have no attestation gate.  |
| Local native evidence     | Run `pnpm check:native --base FULL_SHA` from a clean macOS checkout with that base integrated. Try dirty input, a non-ancestor base, command failure and a changed head.      | Full Rust, hook, supply-chain and native launch checks pass for the recorded head/base/OS. Every negative case fails and temporary hook baselines are removed.                                                                                                       |
| Release preparation       | Inspect manual-only triggers and candidate validation; before a downloadable release dispatch the default workflow with an exact merged SHA.                                  | macOS 14 arm64 checks run only on explicit dispatch. Invalid SHA/ref/history fails. Debug and production app builds launch. Final signed/notarized downloadable bytes still need separate release acceptance.                                                        |
| Integration hooks         | Run temporary successful/failing hooks; remove an installed declaration; test an undeclared hook's absence.                                                                   | Absence before installation is explicit and claims no coverage. Installed failures, invalid hooks and removed default-branch declarations fail.                                                                                                                      |
| Native launch             | On macOS 14 arm64, build the debug app and observe its own AppKit process and main window for two seconds.                                                                    | Launch finishes and the main window persists. The smoke check terminates only its child. WKWebView content, tray behavior and release packaging require separate tests.                                                                                              |
| Supply chain              | Generate from frozen lockfiles with pinned tools; validate CycloneDX schema; compare full notices; exercise drift/license/path fixtures.                                      | Rust/npm components are present without duplicate PURLs. Missing texts, unsupported obligations, notice drift and private artifact paths fail. Only the validated, secret-scanned SBOM is uploaded.                                                                  |
| Secrets and disclosure    | Run scanner/publication regressions and scan source/history/diff/artifacts. Before publication, review final outbound text, linked records, attachments and retained content. | Synthetic secret findings and scanner errors fail with opaque diagnostics. Content changes during a scan invalidate its result. Automated output does not certify semantic disclosure safety.                                                                        |
| Operation and timing      | Inspect the current hosted run; download and independently validate its SBOM; compare a warm-cache run.                                                                       | All four Linux jobs pass for the recorded source/base; local native evidence is recorded separately. Explicit release validation supplies the hosted SBOM. The artifact passes schema, uniqueness, location and secret checks. Warm-cache total is below 12 minutes. |

Before merging, review current source/base identities, run provenance, DCO
and unresolved findings together. Repeat affected checks after a push,
base advance or metadata change. Once the validator is installed on the default
branch, remove `CI_POLICY_SHA` and verify a subsequent run uses that branch.
After merge, verify ordinary PR activity starts no native or publication audit jobs.
Record the first hosted native dispatch only when preparing a downloadable release.

Merge queues remain disabled pending separate live acceptance: execute a group,
verify trusted combined-tree scanning, detect source/content changes during scanning, and exercise
failure paths. Synthetic tests alone do not establish readiness.
