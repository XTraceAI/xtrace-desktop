# Dashboard screen acceptance

`/dashboard` renders the generated `DashboardMetrics` report through `DataSource`. The UI formats values only; every metric, sample count, delta and coverage figure comes from the Rust report. No UI library, chart framework, dependency, storage or DTO was added.

## Layout

The primary composition, top to bottom:

- The TopBar shows the report period immediately before the 7d/14d/30d presets. It updates with the range, is hidden while a range loads and off the Dashboard, and gives the time zone in its tooltip and accessible text.
- Heading "What your agents did", then sessions, human messages, tool calls and favorite model (M-10; an unknown favorite shows `—` with its reason).
- **Agent / human hours**: a compact card with agent hours and estimated human-in-the-loop hours inline ("human est."), and the agent-to-human ratio on a small second line. Each value opens its definition (M-05, M-07 with the estimation method, M-08). Comparisons appear only when the report does not suppress them. Beside it, **Caught by your rules** (R-05) shows `—` and the report's unavailable reason.
- Four StatTiles with full labels: Agent h/day (the note states the day divisor), Concurrency (mean, with max), Merged PRs, and Hands-off median (with p90). Each definition quotes its rule and adds the report note, reason, sample counts and suppressed-delta explanation. The hands-off definition begins "How long your agents run before they need you." and lists the surfaces in `hands_off_excluded_surfaces` with qualifying and degenerate session counts.
- **Effort by type** and **Environment**, at 1.6:1. Effort by type keeps its reserved area and shows the report's unavailable reason, never zero or sample data. Environment is described below.
- **Sessions**: one row per returned active span on the report's fixed 48-hour axis, whatever range is selected. A session with several spans has several rows, keyed by host, session, start and end. Rows show the host glyph and real session ID; screen readers get the full ID and span times. Counts and truncation (`lanes_total`) are labelled as spans. "View sessions" opens the existing Sessions route.

### Environment

Environment reads its own `environment(days)` query (`queryKeys.environment`, refreshed by the shared `metrics` invalidation, including enrichment that adds no record). The Dashboard report's `unavailable.environment` entry is no longer shown. The panel formats values only. It never sums, re-sorts or ranks.

- **Summary.** Selected-range observed calls and the count of identities with a call in either the selected range or the fixed 14 local days (`totals`), plus an `Inventory unknown` pill in the neutral tone.
- **Unresolved attribution.** When `selected_unresolved_calls` is above zero, a one-line warning-toned note states that count on its own ("38 unresolved observations", plus "including untimed" when a `missing_timestamp` group exists). It never shows it as "X of Y" or as a share of the observed calls. `selected_unresolved_calls` includes observations with no timestamp, which no window holds and `selected_calls` excludes, so any such fraction would be false. The note's **Details** button ("Unresolved attribution details") opens a dialog that lists each host and reason from `selected.unresolved` in two groups:
  - **In the last N d**: hook summary events (hooks ran, not which one), unknown kind, unstated MCP detail and unstated skill name;
  - **Untimed**: `missing_timestamp` groups, stated as untimed observations that cannot be assigned to any selected range and are not part of the range's observed calls.
- **Top eight rows.** The first eight `identities`, in the order the report gives, in a bounded list (about six dense 24px rows visible) that scrolls inside the card and takes keyboard focus. Each one-line row shows:
  - the raw kind badge (an unknown kind reads `unknown kind`, and a future kind is shown verbatim);
  - a truthful name: `server · tool` for MCP and the skill name for a skill, or the raw name with what was not stated (`kind not recorded`, `MCP server and tool not stated`, `skill name not stated`), then the host. A name too long for the line is truncated, and its title holds the full name, note, kind and context;
  - selected-range calls;
  - the fixed 14-local-date `DayStrip` from `strip`, shaded at 0, under 3, under 8, and 8 or more.
    Hook summary rows read "Hook summary events" and count events, never calls of a named hook.
- **Compact row.** Effort by type and Environment stay at 1.6:1 and share a height. With the dense synthetic report the card is at most 400px at 1440×900 and 440px at 1120×720, so Sessions stays in the first 1440×900 view.
- **Range.** 7/14/30 changes the selected calls and totals. The strips keep the same 14 dates, disclosed with the zone in a note. The sidebar is unchanged.
- **No inventory claims.** Installed components are unknown. The panel shows no used/installed ratio, no not-installed label and no never-called claim.
- **Dialogs.** The kit `Modal` (BaseUI Dialog) holds three dialogs. Each is keyboard-operable, traps focus and returns focus to its trigger.
  - **Unresolved attribution**: as above.
  - **Observed identities · N** opens the **Observed identities** dialog and appears whenever any identity is observed. It lists every row in report order, in a focusable, scrollable list, each with its kind badge plus host and raw surface context, looked up in `selected.observed` (or `strip.observed` for a strip-only row), with `unknown surface` for `null`.
  - **Configured components · N** lists `configured` (host, kind, name, source, scope and enablement), stating that being configured does not show that a component is installed, callable or called. It also lists per-source and root statuses. Plugin caches sit in a separate **Cache only** section. Discovered file paths and command, URL, environment and secret values are omitted. Configured names remain visible, including names containing a path or URL.
    - An empty `configured` list reads "No configured components were verified." When any source is incomplete, malformed, unreadable or unsupported, it adds that those sources were not fully read, so components may be configured that it does not show. It never says the supported files name no component.
    - An `entry_limit` count from a directory source (the Claude skills directory and both plugin caches) is a lower bound, because the listing stops one past the bound. It reads "at least N entries, at least M skipped … both are lower bounds". A file over the bound states its full count and keeps its exact figures.
- **States.** Loading, a safe error without backend text plus "Retry environment usage", and an empty observation. None of these hides the rest of the Dashboard.

Supplementary measurements follow in collapsed sections; each keeps its title, rule and summary visible, and its expanded state survives a range change:

- **Tokens per day** (M-04), captioned with the recorded total and `usage_coverage.total` measured/sessions: one row each for fresh input, output and cache read, each on its own scale labelled "measured peak" (a series with no numeric counter says "no recorded measurement"; a measured zero peak stays 0), with a table of every day's counters including cache writes and total. There is one entry per returned local date bucket, including partial dates. A day without selected usage is "no recorded usage", a null counter is a dashed "unmeasured" bar, and a measured zero stays 0.
- **API-equivalent cost**: total, catalog version, `as_of`, basis, priced and unpriced response counts, and each unpriced model/tier with its reason. When `total_usd` is null, the total shows `—`; a priced subtotal is described as partial and never shown in the total slot.
- **Coverage**, summarized with the inventory state: token measurement (total and by surface, gaps named, fixed trailing-14-day gate); session capture with the inventory state (only `fresh_complete` uses the success tone; `unknown` is neutral; an empty list reads "No session capture coverage rows available.", which does not prove there are no receipts) and a note that historical receipts do not mean a surface is capturing now; hands-off timestamp-health exclusions.
- A one-line native index status (phase and freshness), stating that indexing does not certify capture coverage, with a link to the full diagnostics in Settings.

Percentages in the report are percentage points (50 means 50%). `present.ts` divides by 100 exactly once before the kit fraction formatters. Suppressed deltas are not shown.

When a tile's values (for example mean, change and max) do not fit beside its full label, the value row wraps below the label rather than truncating it. At a Dashboard width under 1040px (1120×720 windows), tiles become a 2×2 grid; paired cards stack only under 720px. At 1440×900 the primary composition through the Sessions lanes fits in the first view. The page scrolls vertically without horizontal overflow.
